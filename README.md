# boxing-leads-bot

Личный бот: ищет в Threads публичные посты, где люди просят посоветовать тренера по боксу, занятия или место для тренировок **в Варшаве**, и присылает их в ваш личный чат Telegram. В карточке есть текст поста, автор, время, причина совпадения, готовый вариант ответа на языке автора и кнопки «Открыть в Threads», «Ответил» и «Пропустить».

Стек: один процесс на Node.js и TypeScript, нативный `fetch` для Threads API, grammY для Telegram, SQLite через better-sqlite3.

## Требования

- **Node.js 22.12+** (рекомендуется 24 LTS, см. `.nvmrc`), npm.
- macOS или Linux.

```bash
npm ci
```

## 1. Офлайн-демо (ключи не нужны)

```bash
npm ci
npm run demo
```

Демо показывает, какие примеры проходят фильтр и почему остальные отброшены, а также как выглядит карточка в Telegram. Используются те же матчер и форматтер, что и в продакшене. Демо не читает `.env`, работает с временной SQLite (она удаляется после запуска), а `fetch` в нём заблокирован.

## 2. Telegram

1. Откройте [@BotFather](https://t.me/BotFather), выполните `/newbot` и скопируйте токен.
2. Выполните `cp .env.example .env` и впишите `TELEGRAM_BOT_TOKEN=...`.
3. Откройте своего бота в Telegram и отправьте ему `/start`.
4. Узнайте свои ID локально:
   ```bash
   npm run telegram:whoami
   ```
   Возьмите строку с `chat_type=private` и вашим username. Её `user_id` впишите в `TELEGRAM_OWNER_USER_ID`, а `chat_id` в `TELEGRAM_CHAT_ID`. В личном чате эти два числа совпадают.

Бот отвечает только этому пользователю и только в этом личном чате. Сообщения других людей игнорируются, а первый, кто отправит `/start`, владельцем **не** становится.

## 3. Threads API

1. Создайте приложение на [developers.facebook.com](https://developers.facebook.com/) с use case **Threads API**. Добавьте разрешения `threads_basic` и `threads_keyword_search`.
2. Получите **long-lived** user access token (живёт 60 дней) и впишите его в `THREADS_ACCESS_TOKEN`.
3. **Одобрение публичного поиска.** Без одобрения Meta (advanced access для `threads_keyword_search` через App Review) эндпоинт `keyword_search` ищет **только по вашим собственным постам**. Валидный токен, пустой ответ или выдача, где только ваши посты, **не доказывают**, что публичный поиск работает. Подробнее: [fbsamples/threads_api#72](https://github.com/fbsamples/threads_api/issues/72).
4. **Проверка доступа.** Найдите в Threads свежий (до 7 дней) публичный пост **другого** автора и возьмите из него фразу:
   ```bash
   npm run threads:check -- "фраза из чужого поста"
   ```
   Строка `✅ PUBLIC SEARCH CONFIRMED` означает, что поиск видит чужие посты. `❌ NOT PROVEN` означает, что одобрения нет или фраза не нашлась.

**Продление токена.** Long-lived токен действует 60 дней. Продлить его можно, если ему больше 24 часов и срок ещё не истёк:

```bash
curl -s "https://graph.threads.com/refresh_access_token?grant_type=th_refresh_token&access_token=ТЕКУЩИЙ_ТОКЕН"
```

Новый `access_token` из ответа впишите в `.env` и перезапустите воркер. Если токен истёк, бот один раз сообщит об этом в Telegram, а `/status` покажет «токен Threads истёк».

Как устроен поиск: `GET https://graph.threads.com/v1.0/keyword_search` с параметрами `search_type=RECENT`, `since` = начало окна, `fields=id,text,media_type,permalink,timestamp,username`. Фразы для поиска лежат в `src/searchTerms.ts`. Они намеренно широкие, а строгий отбор (бокс + просьба + Варшава) происходит локально, по правилам из `src/rules.ts`. Лимит Meta — 2 200 запросов за скользящие 24 часа. По умолчанию это 18 фраз × 48 сканов, то есть около 860 запросов в сутки.

## 4. Переменные окружения

Обязательные для живого режима: `THREADS_ACCESS_TOKEN`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_OWNER_USER_ID`, `TELEGRAM_CHAT_ID`. Если какой-то не хватает, программа выводит **имена** переменных (без значений) и завершается с кодом 2. Демо-данные вместо живого поиска она не подставляет никогда.

Необязательные:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `SCAN_INTERVAL_MINUTES` | 30 | Интервал между сканами |
| `LOOKBACK_HOURS` | 24 | Насколько старые посты учитывать (макс. 168) |
| `MAX_REQUESTS_PER_SCAN` | 20 | Потолок запросов к Threads за скан |
| `RESULTS_PER_QUERY` | 50 | `limit` на один запрос (макс. 100) |
| `HTTP_TIMEOUT_MS` | 15000 | Таймаут запроса к Threads |
| `DATABASE_PATH` | `./data/leads.sqlite` | Файл SQLite |
| `THREADS_API_BASE` | `https://graph.threads.com/v1.0` | Базовый URL API |

## 5. Живой smoke-тест (один скан)

```bash
npm run scan:once
```

Команда делает один скан: не больше `MAX_REQUESTS_PER_SCAN` запросов, затем пишет в SQLite и отправляет в Telegram **только** найденные совпадения. В конце выводит итог (`ok`, `partial`, `auth_error`, `permission_denied`, `rate_limited`, `provider_error`), число запросов, постов и лидов, а также ошибки. Код выхода 0 означает полный успех.

## 6. Постоянный воркер

```bash
npm run build
npm start
```

Работает один процесс: long polling Telegram плюс скан сразу при старте и затем каждые `SCAN_INTERVAL_MINUTES`. Сканы не накладываются друг на друга. Остановка — Ctrl+C или `SIGTERM`. Состояние хранится в `DATABASE_PATH`, поэтому держите этот файл на постоянном диске. Чтобы воркер работал в фоне на Mac, удобно запускать его через `pm2` или `launchd`. Запускайте только **один** экземпляр с этим токеном бота.

Команды бота: `/status` (последний успешный скан, число лидов, последние ошибки Threads и доставки) и `/start`/`/help`.

## Как это работает

- **Отбор** (`src/matcher.ts`, правила в `src/rules.ts`). Для уведомления нужны все три признака:
  1. пост про бокс (кикбоксинг и тайский бокс не считаются);
  2. автор просит тренера, занятия или место для тренировок;
  3. место — Варшава или узнаваемый район.

  Реклама тренеров, билеты, турниры, обсуждение боёв и запросы про другие города отсекаются. Фраза «живу в Варшаве, но ищу тренера в Кракове» распознаётся как Краков. Текст нормализуется: регистр, польские диакритики, падежные окончания. Причину совпадения бот объясняет одной строкой.
- **Дедупликация.** Ключ — ID поста в Threads (PRIMARY KEY в SQLite). Он работает между фразами поиска, сканами и перезапусками. Посты, не прошедшие фильтр, не сохраняются.
- **Доставка отдельно от решения.** У лида есть `delivery_status` (`pending` или `sent`) и отдельное поле `decision` (`replied`, `skipped` или пусто). Если Telegram недоступен или отклонил сообщение, лид остаётся `pending` и отправляется на следующем скане. Статус `sent` записывается только после подтверждения от Telegram.
- **Окно дубликата.** Если процесс упадёт *после* того, как Telegram принял сообщение, но *до* записи в SQLite, после перезапуска эта карточка придёт ещё раз. Окно — миллисекунды, и это осознанный компромисс: лучше дубль, чем потерянный лид.
- **Хранение.** Сохраняются только ID, username, текст, ссылка, время поста и ваше решение. Отправленные лиды старше 90 дней удаляются автоматически.
- **Ошибки Threads.** Истёкший токен (код 190), нет разрешения (10/200–299), лимит (4/17/32/613/429; следующий скан пропускает поиск до конца паузы), временный сбой или таймаут (5xx, сеть) и успешный пустой ответ — это разные исходы, и `/status` показывает каждый по-своему.
